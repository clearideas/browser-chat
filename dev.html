Browser Chat – demo

The widget below talks to the local test server (), which returns canned replies and never calls an AI service.

Language sets the page's <html lang>, and the Dark mode switch (top right) sets class="dark" on it. The widget follows both without a reload, and the test server answers in the same language. The demo site's theme mode is “system”: without a page theme, the widget follows the system preference.

This site is hostile on purpose. Its configuration puts script-carrying HTML such as <img src=x onerror=…> into the assistant name, greeting, headline, tagline, disclaimer and hello bubble, plus a script in the icon URL, javascript: and data: links, and CSS in the color. Its content is in English only.

Seeing that markup as plain text in the widget is the expected, safe result: the widget never turns server data into HTML. The unsafe links are dropped, and the icon and color fall back to defaults. If any payload ran, a red banner would appear above.

Try it

  • Open the chat and send any message: the server echoes it back.
  • Voice sites: click the microphone. Realtime voice answers every two seconds of speech with a canned spoken reply (a tone); recorded voice answers a recording with a canned reply and audio. The server does not recognize speech: transcripts are placeholders.
  • Enter a signed-in user ID and send /fixture whoami: the server replies with the ID it received. Each user ID has its own conversation; switching back restores it.
  • Send /fixture help for the reply scenarios: Markdown, citations, errors, dropped connections, stream formats and hostile content. The scenario list and sample replies are in English; greetings, echoes and error messages follow the language.
  • Stop the test server and click the launcher: a “Chat is unavailable” notice appears, and the next click tries again.

The widget stores its session in localStorage (separately for each server and site) and caches configuration for five minutes.
